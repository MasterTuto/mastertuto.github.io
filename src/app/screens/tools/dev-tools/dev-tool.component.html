A JSON formatter online for everyday development

JSON Beautifier Pro turns compact API responses, configuration files and test fixtures into readable JSON. Indentation makes nested objects easier to follow, while live validation helps you find syntax mistakes before you copy data into an application. All processing happens in your browser, so you can work without creating an account or sending the document to a formatting service.

Use two spaces for a compact view, four spaces for a more pronounced hierarchy, or tabs to match your editor. Switch to Minify when you need a compact one-line value for a request body or a test fixture. Formatting preserves the order of keys, number literals and string escapes, including integers larger than JavaScript’s safe integer range.

How to format, validate and minify JSON

  1. Paste your JSON in the input editor, or load the example to try the tool.
  2. Read the validation status. Correct any reported syntax errors in the original input.
  3. Choose your indentation and select Beautify for readable output, or Minify to remove unnecessary whitespace.
  4. Copy the result. On a phone, scroll below the input to reach the output and its copy button.

The input remains unchanged when you switch output modes. Invalid input clears the result so that you cannot accidentally copy an older, unrelated document. Browser error messages include a line and column when a character position is available.

Common JSON errors and how to fix them

JSON requires double quotes around property names and string values. Single-quoted JavaScript strings, unquoted keys, comments and trailing commas are not valid JSON. Separate object properties and array items with commas, and check that every opening brace or bracket has a matching closing character.

Use lowercase true, false and null. Values such as undefined, NaN and Infinity belong to JavaScript and cannot appear as JSON values. A line break inside a string must be escaped. This tool validates JSON syntax; it does not validate business rules or a JSON Schema.

JSON formatter FAQ

What is the difference between beautifying and minifying?

Beautifying adds line breaks and indentation to make structure easier to read. Minifying removes whitespace outside strings. Both produce the same JSON values, and spaces inside text are preserved.

Can I format an array or a primitive value?

Yes. A JSON document can contain an object, an array, a string, a number, a boolean or null at its top level. An empty input is not a JSON document.

Will large numbers or duplicate keys change?

The formatter preserves number text and duplicate keys instead of rebuilding the document with JSON.stringify. Duplicate keys can still be interpreted differently by consuming applications; avoid them for interoperable data. Formatting cannot restore precision already lost before pasting.

Does this support JSON5, comments or very large files?

This is a strict JSON formatter, not a JSON5 parser. Remove comments and trailing commas first. Input is limited to one million characters to keep this interactive tool practical; use a local editor for larger documents.

A JWT decoder online for inspecting token contents

JWT Token Decoder helps you examine the header and payload of a JSON Web Token while debugging an authentication flow or learning how token claims work. Paste a compact three-part token and see the decoded JSON, registered claims and UTC timestamps in one place. You can also paste an Authorization header value beginning with Bearer.

A typical signed JWT contains a header, a payload and a signature separated by dots. The first two parts use Base64URL encoding, which is reversible and does not hide their contents. This tool decodes those parts locally. It does not require a secret, contact the issuer or verify cryptographic signatures.

How to decode a JWT and check expiration

  1. Paste your token or load the clearly unsigned example.
  2. Inspect the header to see the declared algorithm and any key identifier.
  3. Read the payload and claim descriptions. Expiration, not-before and issued-at values are shown as UTC dates when they are valid NumericDates.
  4. Review the timing status, then copy the header or payload if you need readable JSON for debugging.

Time checks use your device clock. A token is marked expired when the current time reaches its exp value. A future nbf indicates it is not active yet. A missing expiration is reported explicitly, and string timestamps are flagged instead of silently converted into numbers.

Understanding registered JWT claims

iss identifies the issuer, sub identifies the subject, and aud identifies the intended audience, which may be a string or an array. jti is a token identifier. Application-specific claims such as roles and permissions appear alongside these registered fields.

exp is the expiration time, nbf is the earliest time the token may be accepted, and iat records when it was issued. These NumericDate values count seconds since the Unix epoch, not JavaScript milliseconds. Applications decide which claims are required and must validate them as part of their own authentication rules.

JWT decoder FAQ

Does decoding prove that a JWT is valid?

No. Anyone can construct a decodable header and payload. A trusted verifier must check the signature with the correct key, restrict allowed algorithms, and validate relevant claims such as issuer, audience and expiration. Never grant access based only on this page’s output.

Why is my token rejected?

The decoder expects three dot-separated parts and Base64URL-encoded UTF-8 JSON objects in the header and payload. Incomplete copies, quotes around the token, internal whitespace or non-JSON content can cause errors. A five-part encrypted JWE requires decryption and is not supported here.

Why can I read a token without a secret?

Encoding is different from encryption. The header and payload of a typical signed JWT are readable by anyone holding it. The signature protects integrity when correctly verified; it does not make the payload confidential.

What if there is no exp claim?

The tool reports that the token does not declare an expiration. This does not establish that it is acceptable: your application may require exp or apply its own lifetime policy. An issued-at timestamp alone is not an expiration date.

Protocol reference: RFC 7519 — JSON Web Token (JWT).
